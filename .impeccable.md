## Target audience

Operations / finance teams in construction & contracting companies who reconcile **purchase orders (PO) ↔ delivery notes (DC) ↔ invoices (INV)** — the 3-way match. Hebrew-first (RTL), occasional English. Power users who live in this tool all day.

## Use cases (jobs to be done)

1. **Triage discrepancies fast** — see at a glance which line items mismatch and why.
2. **Trust the numbers** — every quantity, price, and total must be visibly precise (no silent rounding that hides shortages).
3. **Drill into a single document or vendor** without losing context.
4. **Take action on exceptions** — override, substitute, mark duplicate, approve price increase — with a clear paper trail.
5. **Prove the match** — show the user WHY the system thinks something matches or doesn't.

## Brand personality / tone

- **Confident & precise** — this is a money-handling tool. Numerical precision and visual order signal trust.
- **Calm, not loud** — the interface should not shout. Status colors are reserved for status; brand colors are reserved for document types.
- **Information-dense, not cluttered** — power users want everything on one screen, but with clear hierarchy.
- **Hebrew-native** — RTL layouts, Hebrew typography (Inter for Latin, default Hebrew sans), idiomatic Hebrew copy (NOT translated-feeling).

## Brand color system (from Sagur DOCUMENT_UI_SYSTEM.md)

The 3-way match has a tri-color palette mapped to each document type:

| Color | Hex | Tailwind | Document | Usage |
|---|---|---|---|---|
| Cyan / Light Blue | `#55c8e4` | `primary` | **Purchase Order (PO)** — *Initiation* | PO badges, primary CTAs (Create PO, Approve Match, Save) |
| Soft Purple | `#8c5fa8` | `secondary` | **Delivery Cert (DC)** — *Bridge* | DC badges, secondary actions (Edit, Upload DC, Filter) |
| Deep Violet | `#2d1b4e` | `accent` | **Invoice (INV)** — *Conclusion* | INV badges, heavy structural actions (Export, Lock Period, Finalize) |

**Reserved for status (DO NOT use brand colors for status):**
- `success` (green `#10B981`) — match / fulfilled
- `warning` (amber `#F59E0B`) — pending / partial
- `error` (red `#EF4444`) — discrepancy / overbilled
- `info` (sky `#0EA5E9`) — neutral info

**NEVER hardcode brand hex values with Tailwind.** Always use the semantic tokens (`bg-primary`, `text-secondary`, `bg-accent/10`, etc.) so the dark theme in `tailwind.config.js` works.

## Typography

- Sans: `var(--font-inter)` (Latin) — already set up at the app level
- Mono: `var(--font-fira-code)` — for numerical columns, IDs, doc numbers
- Hebrew uses the system Hebrew sans paired with Inter
- Numerical columns: always `font-mono tabular-nums` (so digits align in tables)

## Layout & density

- Tables are the primary surface — high density, sticky headers, virtualized
- Modals for create/edit flows (see Sagur's `*-modal.tsx` files)
- Sidebar nav (see Sagur's nav patterns)
- Dark mode is first-class — `base-100: #0A0A0A`, `base-200: #141414`, `base-300: #262626` (borders)

## Conventions specific to this codebase

- **Frontend:** React + MobX (RootStore + `useStores()`) + Vite, in `apps/web`
- **i18n:** ALL user-facing strings via `react-i18next` — never hardcode Hebrew or English in JSX
- **Components:** arrow functions, one component per file, no `index.ts` barrels, complex components as folders
- **Always use CSS variables** for brand colors — no hardcoded hex with Tailwind
- File size and comment length limits apply (see CLAUDE.md / memory)
